```sh

```

- `package.json`

- `tests/**`

- `pnpm-lock.yaml`
- `mise.toml`、`tsconfig.json`、lint / formatter config などの local development tooling

## Known constraints

- Initial Scope は single Coding Orchestration。複数 Worker branch、Work Package parallelism、複数 Coding Orchestration は Future Scope。
- Future Scope の Context Routing、Conditional Stage 判定、任意の Escalation Target、Validation Failure classifier は release scope 外。
- Pi / `pi-subagents` / Plannotator の public contract を前提とし、current host が status / resume の reconciliation adapter を提供しない場合は retained child / orphan Worker を推測せず `blocked` / `unsupported` とする。
- Live Jev は `jev.runtimePolicy` の exact `workflowId`、absolute `projectRoot`、`destination`、evidence categories、finite `maxRequests` を要求する。scope 不一致、consent 不在、budget exhaustion、reservation failure は network request を行わず `blocked`。
- `/typesafe enable` は pi-orchestrator の Product Runtime authorization ではない。TypeSafe credentials と network 到達性は operator の責任である。
- Human Plan Gate / Human Code Gate は Plannotator と Human approval が必要で、Agent / Jev による代替や bypass はない。
- Herdr は real Pi smoke の development/test harness であり、runtime dependency ではない。`tmux` はサポート topology ではない。

## Final diff boundary

Release preparation で変更するのは、package metadata、root usage documentation、release notes、release evidence、LICENSE、および ORCH-020 の completion link に限定する。唯一の test 差分は、既存 ORCH-020 の `stronger retry consumes both budgets and cannot downgrade on routing re-evaluation` scenario の default 5 秒 timeout を 10 秒へ広げたもので、assertion / fixture / runtime behavior は変更しない。`src/**` の runtime behavior は変更しない。
